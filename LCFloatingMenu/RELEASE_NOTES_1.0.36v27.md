# LCFloatingMenu 1.0.36v27

## 修复：游客进程读不到设置（保活时长/开关不生效）

`LCOrbitStorage.rootPath` 只认 `getenv("LC_HOME_PATH")`。这个变量是 LC 从宿主
透传给游客的，`LiveProcess/main.m` 里只有非空才 `setenv`；透传不到时整个偏好
系统会静默回落到默认值：

- 保活时长永远是默认 **20 分钟**（你设 10 分钟也按 20 跑）
- 保活开关永远是**开**（关掉之后已在跑的游客照样继续保活）
- 其他设置（外观、微珠参数）同理，只是那些只有宿主在读，所以一直没暴露

现在按可信度排三个候选，并且优先选真正有 `config.json` 的那个：

1. `LC_HOME_PATH` — 宿主正常走这条
2. `LP_HOME_PATH` — LiveProcess 里必定设置，值就是 LC 容器 HOME
3. 从本 dylib 的位置反推（`<root>/Documents/Tweaks` 往上找 Tweaks）

优先选有 `config.json` 的，是因为 `LockRoot` 会 `createDirectory`，误选一个
可写但错误的目录会当场凭空造一份空配置，之后就一直读那份空的了。

## 修复：红色「失去响应」误报

`beat` 只由看门狗周期写入。看门狗关闭后，「后台 + 开关开 + 未超时 + 没在播」
这个窗口没人更新 `beat`，90 秒后原逻辑判红「失去响应」，进程其实好好的。

判红条件加上 `watchdog != 0`，并补两个黄色状态：

| 情况 | 状态 |
|---|---|
| 看门狗开、暂时没播 | `已经停止 · 看门狗会拉起` |
| 看门狗关、后台没播 | `没有巡检 · 看门狗已关` |
| 看门狗开、90 秒没心跳 | `失去响应 · N 秒无回应`（红） |

## 保活面板文案与历史

- `前台不播 · 回到后台自动续` → `前台不保 · 回后台重新计时`。
  回后台是 `gBackgroundStart = FMKNow()` 且 `gTimedOut = NO`，从头算满
  10/20/30 分钟，不是接着余额续。
- 状态词统一四个汉字，两行都以四字开头：
  ```
  正在保活 · 已 3 分 12 秒 · 18 秒前有响应
  上次保活 · 20 分钟 · 46 分钟前停（到时长）
  ```
- 新增「上次保活」：上一轮持续多久、什么时候停的、为什么停。切回前台后
  第一行变成「前台不保」，但这一行仍然保留。
- 去掉「心跳」术语，改成「N 秒前有响应」，直接回答「多少秒前还活着」。

## 状态文件移出插件目录

`keepalive-*.json` 原本直接写在 `Documents/Tweaks/`，LC 的插件页会把目录
条目列出来，那几个 json 混在插件列表里。现在改到：

```
Documents/LCOrbit/state/keepalive-host.json
Documents/LCOrbit/state/keepalive-<bundle>.json
```

- 和 `config.json` 同一个父目录，Filza 里看得见、能手动清
- 不在 `Tweaks/` 下，插件页不会列出来
- **文件名固定**：进程重启覆盖同一个文件，数量天然封顶（1 + 用过几个 App），
  不依赖清理逻辑是否可靠

清理规则（进程启动时执行）：

1. 文件里记录的 pid 已不存在（`kill(pid,0)` 返回 `ESRCH`，`EPERM` 保留）
2. 超过 24 小时没更新过
3. 总数超过 32 份时删最旧的（兜底，正常永远碰不到）
4. 旧位置（`Tweaks/` 根、`Tweaks/.lcfm/`）的遗留文件一并删除

## 升级说明

v26 起自动更新已能识别任意文件名，所以这一版可以直接在应用内更新，
不需要再手动导入。更新后建议重启 LC 和相关 Guest，让所有进程都加载新版本。

装好后可以这样确认：

1. `Documents/LCOrbit/state/` 出现 `keepalive-host.json`
2. `Documents/Tweaks/` 里之前的 `keepalive-*.json` 消失
3. 游客跑满一轮后显示 `到达上限 · 10 分钟`（而不是 20）
